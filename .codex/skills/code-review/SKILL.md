# code-review

Leia Issue, spec, plan, tasks e diff. Confira critérios atendidos e requisitos rastreados; identifique escopo inventado. Avalie testes relevantes, acessibilidade da UI, privacidade dos dados, tratamento de erros, regressões, documentação e necessidade das dependências.

Verifique complexidade desnecessária, duplicação relevante e padrões divergentes; não exija refactor sem benefício concreto. Diferencie erro bloqueante, dúvida de produto e sugestão opcional. Reporte arquivo/local, impacto e evidência reproduzível.

Não declare a Issue concluída com checks falhando ou sem testes pertinentes. Não faça merge, feche Issues nem altere o GitHub como efeito de uma revisão somente de leitura.
